# LuCI с любой темой: правила MedveModem

[English original](LUCI-THEMES.md) · [Документация](README.md)

Источник для изучения поведения: руководство по оформлению приложений темы footstrap из проекта [luci-theme-footstrap](https://github.com/VizzleTF/luci-theme-footstrap), прочитанное 02.11.2026. Чужой код не копировался. Разработчик проверяет Bootstrap и footstrap; совместимость с Aurora проверялась в r129.

Тема footstrap работает как SPA: переключение страниц не обязательно перезагружает документ, поэтому добавленные стили и обработчики могут повлиять на следующие страницы.

## Правила

1. **Время жизни CSS.** Стили, использующие исключительно собственные классы, могут находиться в `<head>`: например, `dashboard.css` или `#mmb-css`. Нельзя глобально переопределять `.cbi-*`, `table`, `th`, `pre`, `h4` вне корня компонента: в SPA-теме это испортит оформление других страниц.
2. **Имена.** Классы и идентификаторы MedveModem начинаются с `mm-`, интерфейса бота — с `mmb-`. Собственные CSS-переменные — только `--mm-*`. Запрещены общие сбросы `* { … }`, фреймворк поверх LuCI и неограниченные правила на `:root`.
3. **Цвета.** Используется контракт темы из 26 переменных: `--background-color-{high,medium,low}`, `--border-color-{high,medium,low}`, `--text-color-{highest,high,medium,low}`, `--{primary,success,warn,error}-color-{high,medium,low}`, а также `--on-{primary,success,warn,error}-color`. Обязателен запасной литерал: `var(--warn-color-medium, #9a6700)`. Имя семейства — `warn`, не `warning`; `--text-color` без уровня нет. Для текста на цветной плашке используют `--on-*-color`, а не постоянный `#fff`. Внутренние `--fs-*` темы footstrap не используются.
4. **Тёмная тема.** Учитывать `:root[data-darkmode="true"]` для Bootstrap и footstrap. Медиаусловие `@media (prefers-color-scheme: dark)` должно быть защищено `:root:where(:not([data-darkmode="false"]))`. footstrap также выставляет `data-theme` и `data-bs-theme`. Предпочтительнее вообще не определять тему вручную, а использовать цветовой контракт.
5. **Адаптивная раскладка.** Рабочая колонка уже окна браузера из-за боковой панели (~224 px). Подбирать оформление через `@container`: `.mm-root` является контейнером `inline-size`. Не задавать жёсткую ширину контейнеров в пикселях и не опираться только на `@media (max-width)`.
6. **SPA-жизненный цикл.** Работать в `render()`, а не в `window.onload`; опросы — через `L.Poll`. Не прикреплять долгоживущие элементы к `<body>`, не регистрировать `popstate`-обработчики. Уведомления размещаются внутри `#view`, а не в `.mm-root`. Штатные Save/Apply скрывают через `handleSaveApply = null`, не CSS.
7. **`!important`.** Допускается только внутри собственного дерева компонентов, не для переопределения чужих глобальных правил.

## Состояние на 02.11.2026

| Правило | Состояние |
|---|---|
| 1. Изоляция CSS | Выполнено: `dashboard.css` и `#mmb-css` ограничены `mm-` / `mmb-`; две неиспользуемые `.fx-*` удалены |
| 2. Именование | Выполнено |
| 3. Цвета | Частично: большинство переменных с fallback, отдельные индикаторы и графики содержат фиксированные цвета |
| 4. Тёмная тема | Выполнено через `data-darkmode` и защищённый media query |
| 5. Раскладка | Частично: 19 запросов `@container`; в таблице статуса и вкладках остаются `@media (max-width)` |
| 6. SPA | Выполнено: нет onload / popstate / интервалов, уведомления перенесены в `#view` |
| 7. `!important` | Выполнено: восемь применений внутри `.mm-root`, `.mm-modem`, `.mm-status` |

Осталось заменить фиксированные цвета на переменные темы и перевести телефонную раскладку блока статуса с ширины viewport на ширину контейнера.
