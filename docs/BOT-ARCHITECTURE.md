# MedveModem Telegram Bot: архитектура, функции и макеты экранов

**Аудит исходников:** 19 ноября 2026 года  
**Репозиторий:** [Medvedolog/medvemodem](https://github.com/Medvedolog/medvemodem)  
**Проверенная ветка:** main, commit 6cee6d38c836404decb45b5ae69d517ae408cae9  
**Версии пакетов в исходниках:** MedveModem Alpha 1 r10; отдельные пакеты medvemodem-bot и luci-app-medvemodem-bot.

**Назначение:** описание фактической реализации по коду, включая Telegram UI, LuCI, границы полномочий и выявленные расхождения. Это не подтверждение аппаратной приёмки или работы каждого сценария на реальном Telegram-аккаунте.

> Макеты ниже — текстовые wireframe-карточки, составленные по фактическим render-функциям и callback-кнопкам бота. Они показывают структуру сообщения и inline keyboard, а не являются скриншотами Telegram. Значения в примерах условные.

## 1. Назначение и модель работы

MedveModem Bot — отдельный Telegram-клиент для администрирования роутера с MedveModem. Он предоставляет:

- уведомления о состоянии интернета, модемов, резервных каналов и служб;
- краткую сводку и карточки модемов;
- журнал событий и выгрузку журналов;
- просмотр входящих SMS и пересылку новых SMS;
- опциональную отправку SMS и USSD;
- просмотр сети, внешних IP, туннелей и проверку доступности сервисов;
- экран ограничений доступа / «Белые списки» и тест блокировок;
- просмотр и изменение лимитов SIM;
- опциональное управление модемами и исключениями автоматического переключения;
- настройки уведомлений и маршрутов связи с Telegram;
- уведомление о доступном обновлении MedveModem.

**Базовый принцип:** бот не является вторым движком модемов. Состояние модемов и их возможности он получает у MedveModem через ubus. Управляющие действия выполняются через API движка и только при включённом разрешении. Бот не открывает AT-порты, QMI/MBIM control nodes и не запускает собственный dialer.

Есть два ограниченных исключения, которые важно учитывать при чтении кода:

1. Редактор лимита трафика записывает UCI-настройку SIM в конфигурацию MedveModem, адресуя её по ICCID, полученному от движка. Сам ICCID в Telegram не выводится.
2. Сетевой helper читает адреса, маршруты, процессы и состояние туннельных менеджеров роутера. Это диагностические чтения, а не управление модемом.

### 2.2. Жизненный цикл

1. Procd запускает ucode runtime из /usr/share/medvemodem-bot/main.uc.
2. Бот проверяет конфигурацию, токен, CA bundle, права на секреты и наличие администратора либо временного pairing window.
3. Бот открывает ubus-соединение, подписывается на события medvemodem.* и публикует собственный объект medvemodem.bot для LuCI.
4. С интервалом до 60 секунд обновляет проекцию состояния модемов, uplink и статуса движка. События и быстрые изменения обрабатываются отдельно.
5. Отдельная задача выполняет long polling Telegram, отдельная — отправляет сообщения и документы. Их маршруты настраиваются независимо.
6. Уведомления проходят через очередь, дедупликацию и правила эпизодов. Действия администратора сначала подтверждаются, затем выполняются через движок.
7. При остановке процесса временные транспортные файлы очищаются; procd отвечает за повторный запуск.

Бот использует uloop и ограниченное число асинхронных задач. Медленный ответ Telegram или движка не должен превращать всю работу бота в одну синхронную операцию.

### 2.3. Маршруты до Telegram

Маршруты polling и send разделены: получение команд и отправка уведомлений могут идти разными путями.

В зависимости от конфигурации и обнаруженных сервисов используются:

- локальные прокси, обнаруженные на роутере;
- вручную добавленные SOCKS5h / HTTP / HTTPS прокси;
- прямое подключение;
- другие доступные модемные каналы;
- резервный IPv4-маршрут, если он задан администратором.

Автоматически распознаются, в частности, Podkop, Podkop Plus, Forkop, NetShift, SSClash, nikki и JustClash. Бот читает их конфигурацию и состояние; он не включает и не перезапускает эти менеджеры.

SOCKS используется как socks5h, чтобы DNS-имя Telegram разрешалось через прокси. MTProto-ссылки Telegram App не являются транспортом для Bot API.

Режимы маршрута в LuCI:
- **Auto** — прокси по порядку, затем разрешённые резервные способы;
- **Proxy only** — только прокси, без прямого fallback;
- **Direct** — прямое подключение без прокси.

Параметры polling и send независимы. Для прямого маршрута можно задать интерфейс Linux; эта привязка не применяется к прокси.

### 2.4. Очередь и повторная доставка

Исходящие сообщения проходят через queue.uc. В интерфейсе LuCI доступны счётчики pending / inflight / uncertain, объём очереди и число отброшенных информационных сообщений.

В коде RPC статуса очереди заданы пределы: 200 элементов и 262144 байта. Повторные отправки ограничены, а неоднозначный результат не трактуется как гарантированная доставка.

Содержимое SMS и USSD помечается как raw/secret и не должно попадать в сохраняемую очередь или журнал. Для SMS/USSD остаются только обезличенные служебные события вроде sms_sent, sms_send_failed, ussd_done.

### 2.5. Данные и хранение

| Данные | Где находятся | Примечание |
|---|---|---|
| Основные настройки | /etc/config/medvemodem-bot | UCI |
| Telegram token и proxy secrets | /etc/config/medvemodem-bot-secret | root-only, mode 0600 |
| Salt/HMAC key | /etc/medvemodem-bot/salt | root-only, mode 0600 |
| Рабочее состояние | /tmp/medvemodem-bot | tmpfs |
| Счётчик Telegram update offset | /tmp/medvemodem-bot/offset.json | для продолжения polling |
| Сводный snapshot | /etc/medvemodem-bot/state/summary.json | только ограниченные HMAC fingerprints; не журнал SMS |
| Суточная история | /tmp/medvemodem-bot/daylog.json | состояния и временные метки; сбрасывается после перезагрузки роутера |

Опция snapshot_minutes управляет частотой сводного snapshot; значение по умолчанию — 15 минут, 0 отключает его.

## 4. Команды Telegram

Команды регистрируются через Bot API setMyCommands для личного чата администратора. Постоянной reply-клавиатуры под полем ввода нет; используется меню команд Telegram и inline-кнопки внутри карточек. Старые текстовые кнопки из прежней reply-клавиатуры ещё распознаются для совместимости.

| Команда | Экран / действие |
|---|---|
| /start | Приветственная сводка; удаляет старую reply-клавиатуру |
| /menu | Главная сводка с inline-меню |
| /status | Состояние роутера, движка, бота, памяти и сводка за сутки |
| /modems, /modem | Список модемов |
| /modem1, /modem2 … | Карточка модема по позиции в списке |
| /channels, /uplinks | Каналы доступа в интернет |
| /quota | Лимиты трафика SIM |
| /events | Последние события |
| /log | Журнал модемов файлом |
| /logall | Полный журнал роутера файлом |
| /sms | Входящие SMS |
| /send | Отправка SMS |
| /ussd | USSD-запрос |
| /network | Сеть, внешние адреса, туннели и проверки |
| /settings | Настройки уведомлений и прокси |
| /help | Справка |

«Белые списки» и исключения failover доступны через inline-меню, отдельной slash-команды для них в списке setMyCommands нет.

Состав полей зависит от доступности телеметрии:
- модель, физическое присутствие, состояние сессии и интерфейс;
- роль канала и состояние проверки интернета;
- SIM, оператор SIM и фактическая сеть регистрации;
- RAT, регистрация, signal percent, RSRP/SINR и оценка помех;
- задержка/ограничение/недоступность интернета;
- длительность подключения, downtime за сутки и квота;
- стабильность и состояние recovery;
- действие, требующее вмешательства администратора;
- статус замороженного модема.

Если данные старые, карточка маркирует их как последние известные и не показывает зелёный статус как текущий.

Кнопки управления появляются только при allow_control=1, для присутствующего модема и свежих данных. Действия идут через MedveModem API. Кнопка SMS/USSD не находится в этой карточке: эти сценарии открываются из раздела входящих SMS или командой.

    Пришлите текст сообщения.

- отображается расчёт частей GSM-7/UCS-2;
- черновик живёт в памяти 10 минут;

- номер и текст не записываются в журнал или постоянную очередь.

### T-26. Автономные уведомления

Типовые сообщения формируются из эпизодов, а не из каждой строки журнала отдельно.

**Потеря подключения:**

    🔴 Подключение прервано · FM350
    Интернет доступен через «T99W175».
    MedveModem восстанавливает подключение.

**Восстановление:**

    ✅ Подключение восстановлено · FM350
    Перерыв: 4 мин
    Связь восстановлена после: «переподключение сессии».

**Частые короткие сбои:**

    〰️ Подключение: частые короткие сбои (3)
    Интернет доступен через «T99W175».

Другие виды:
- отключение/возврат модема на USB;
- интернет недоступен или ограничен белым списком;
- основной канал сменился;
- ModemManager или QModem остановился/перезапустился;
- MedveModem перезапущен — одно сводное сообщение вместо отдельных «подключился» для каждого модема;
- аппаратные события ядра: USB controller, undervoltage, kernel oops/panic, hung task, OOM, перегрев и другие известные классы;
- исчерпание/предупреждение лимита;
- новые SMS, если разрешены и включена пересылка.

Короткие события коррелируются в окне эпизода. В smart-режиме после трёх коротких сбоев может прийти отдельное сообщение о flapping. После рестарта есть короткий период тишины, затем отправляется одна сводка.

## 6. LuCI: экраны бота

### L-01. Overview — обзор

Страница показывает:
- установлен ли пакет и отвечает ли RPC бота;
- работает ли процесс, имя Telegram-бота, состояние токена и администратора;
- результат TLS/preflight и доступность CA bundle / системного времени;
- версии бота и движка;
- polling и send: состояние, последний успешный запрос, текущий маршрут, конфликты polling;
- очередь: pending, inflight, uncertain, dropped, размер;
- список маршрутов, тип (proxy/direct/modem/emergency), текущий ли маршрут, время и результат последней проверки;
- найденные локальные proxy managers и советы по настройке mixed port.

Действия:
- обновить состояние;
- перезапустить только службу бота;
- отправить тестовое сообщение;
- поставить проверку конкретного маршрута или группы маршрутов.

Обзор не управляет модемами и не перезапускает proxy managers.

### L-02. Setup wizard — мастер настройки

Четыре шага, каждый со своим состоянием done/current:

1. **Bot token.** Токен от @BotFather вводится в password field, сохраняется в закрытый файл, поле очищается; затем выполняется проверка Bot API.
2. **Reaching Telegram.** Проверка прямого маршрута, ввод прокси SOCKS5h/HTTPS, проверка прокси перед включением. Можно отдельно проверить без прокси.
3. **Administrator.** В текущем JavaScript wizard вводится числовой Telegram user ID. Это не поле @username.
4. **Start-up.** Включить/перезапустить только службу бота и проверить фактическое состояние через RPC why; доступна отправка тестового сообщения.

Кнопки Back/Next и верхние step chips позволяют возвращаться к шагам. После завершения есть переход в Overview.

### L-03. Settings — настройки

Форма содержит группы:

**General**
- включение бота;
- язык auto/ru/en;
- разрешение управления модемами из Telegram (allow_control);
- разрешение изменения настроек из Telegram (allow_settings);
- период сводного snapshot.

**SMS to Telegram**
- показывать SMS (allow_sms_content);
- пересылать новые SMS (sms_forward, зависит от показа SMS);
- разрешить отправку SMS и USSD (allow_send).

**Administrator**
- Telegram user ID;
- private chat ID.

**Notifications**
- автономные уведомления;
- режим smart / critical / all;
- резервные модемы, перезапуски служб, kernel/hardware, квоты, перезапуск MedveModem;
- тихие часы и начало/конец;
- срочные уведомления со звуком в тихие часы.

**Reaching Telegram**
- отдельные настройки polling и send;
- auto / proxy only / direct;
- direct fallback;
- попытка других модемов;
- интерфейс для direct route.

**Proxies to Telegram**
- добавить/удалить proxy section;
- включить/выключить;
- название, адрес, роль, приоритет;
- проверка каждого proxy.

**Proxy login and password**
- общий login/password для прокси, заданных в LuCI;
- password хранится отдельно, не возвращается в браузер;
- прокси, добавленные через Telegram, могут иметь собственный пароль.

**Danger zone**
- выключить бота;
- удалить Telegram token из закрытого хранилища.

Общие UCI-настройки применяются через Save & Apply. Токен и пароли проходят отдельные RPC методы, не передаются в открытом виде через UCI-форму.

## 7. Права и значения по умолчанию

Начальные значения в files/etc/config/medvemodem-bot:

| Опция | По умолчанию | Смысл |
|---|---:|---|
| enabled | 0 | Бот выключен до настройки |
| allow_control | 0 | Telegram только читает состояние |
| allow_send | 0 | SMS/USSD отправка выключена |
| allow_sms_content | 0 | Тексты SMS не показываются |
| sms_forward | 0 | Новые SMS не пересылаются |
| allow_settings | 1 | Разрешены настройки из Telegram |
| lang | auto | Язык по Telegram client language |
| snapshot_minutes | 15 | Сводный snapshot |
| events.enabled | 1 | Автономные уведомления включены |
| events.mode | smart | Сводные уведомления |
| events.quiet | 0 | Тихие часы выключены |
| events.quiet_from / quiet_to | 23:00 / 07:00 | Интервал, если тихие часы включить |
| events.quiet_urgent | 1 | «Нет интернета» и исчерпанный лимит могут звучать |

Права независимы:
- allow_control не включает отправку SMS/USSD;
- allow_send не включает управление модемами;
- allow_sms_content разрешает показывать содержимое, а sms_forward отдельно включает автономную пересылку;
- allow_settings=0 оставляет Telegram Settings только для просмотра;
- LuCI имеет собственный ACL, и команды записи ограничены конкретным списком методов.

## 8. Безопасность и приватность

- Ответы и callback принимаются только из private chat и только от привязанного user_id/chat_id.
- Неизвестные пользователи и групповые чаты игнорируются.
- Token и proxy passwords находятся в закрытом secret file с правами 0600; token не выводится обратно в браузер.
- Секреты не передаются в argv процессов и не пишутся в системный журнал.
- Номера, SMS body, USSD codes и USSD answers не записываются в журнал или постоянное состояние бота.
- Для сообщений, содержащих чувствительные данные, очередь не должна сохранять raw payload.
- В callback используются короткие opaque keys, а не полный device_id.
- Кнопки действий имеют временную метку; устаревшие кнопки отклоняются.
- SMS читаются через peek и не помечаются прочитанными на модеме.
- Bot code вызывает engine ubus API, а не обращается напрямую к AT/QMI/MBIM устройствам.
- TLS verification включена; при неправильном времени роутера или отсутствующих сертификатах preflight блокирует работу транспорта.
- Административные действия записываются в syslog только как тип действия (admin_*), без текста SMS/USSD и введённых секретов.

## 9. Выявленные расхождения и пределы текущей проверки

Это наблюдения аудита кода, а не предложения менять поведение в рамках этого документа.

### 9.1. Pairing: документация и текущий мастер расходятся

В коде есть backend временного pairing:
- RPC pair_begin создаёт одноразовый 12-символьный код на 10 минут;
- бот принимает /pair CODE в личном чате;
- кандидат сохраняется временно;
- LuCI может получить кандидата через pair_status и подтвердить через pair_confirm.

Однако текущий bot-setup.js не вызывает pairBegin, pairStatus или pairConfirm. Его шаг Administrator просит вручную ввести числовой Telegram user ID и сохраняет его в UCI. Русский и английский README ранее описывали one-time-code flow, а скрипт why также содержит устаревшую подсказку про код.

Поэтому фактический текущий пользовательский сценарий мастера — ввод числового Telegram ID. Pairing API существует, но его нельзя описывать как подключённую кнопку мастера без отдельного подтверждения call-site.

### 9.2. Автоматизированное тестирование бота

В tests/ есть отдельный test-bot-update-versions.sh, проверяющий версионную логику пакетов бота. Общие test-luci-frontend.py и test-luci-browser.cjs в проверенном срезе не содержат тестовых ссылок на bot.js, bot-setup.js, bot-settings.js или botcommon.js.

В репозитории не обнаружен отдельный end-to-end тест Telegram Bot API, который прогоняет реальную цепочку token → long poll → inline callback → action → message edit. Не обнаружен и полный UI smoke-test трёх страниц bot-LuCI. Наличие функций в исходниках не следует приравнивать к такой приёмке.

### 9.3. Документальные ограничения

- Макеты в этом документе воспроизводят структуру render-функций, а не подтверждённый скриншотный вид на всех клиентах Telegram.
- Текст и поля карточек зависят от того, что вернул MedveModem engine и что поддерживает конкретный модем.
- Сетевая проверка и доступность Telegram зависят от внешних маршрутов, proxy managers, DNS, системного времени и CA bundle.
- Документ описывает исходники ветки main на указанном commit. Он не доказывает, что именно этот код установлен на конкретном роутере.
