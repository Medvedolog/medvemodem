# MedveModem — установка и обновление

**Срез документации:** публичная `0.16.0-alpha1-r1`, переименована из `0.15.0-r197` 16.11.2026. Проект в состоянии альфы; наличие исходников **не означает**, что стендовая сборка этой версии опубликована. Проверяйте текущее состояние и [Releases](https://github.com/Medvedolog/medvemodem/releases).

Перед установкой обеспечьте резервный доступ к роутеру: Ethernet, Wi-Fi или локальную консоль, не зависящие от испытываемого модема. Не устанавливайте одновременно другой управляющий менеджер того же модема.

## 1. Выбор пакетов

На роутере:

```sh
. /etc/openwrt_release
echo "OpenWrt: $DISTRIB_RELEASE; архитектура пакетов: $DISTRIB_ARCH"
df -h /overlay
```

Выберите опубликованный архив под точные архитектуру и выпуск OpenWrt; полный состав и различия релизов перечислены ниже. Не путайте пакетную архитектуру с моделью процессора.

Движок статически включает libubox/libubus/libuci, но **остальные зависимости** (например, ModemManager, qmi-utils, jsonfilter, libjson-c) устанавливает пакетный менеджер из подходящих репозиториев. Не заявляйте совместимость со всяким snapshot без проверки пакетов.

## Структура релизов и состав установки

Открывайте **[GitHub Releases](https://github.com/Medvedolog/medvemodem/releases)**, а не исходники в «Source code» и не временные артефакты Actions. Для одного роутера нужен **один** архив MedveModem, точно соответствующий `DISTRIB_ARCH` и версии OpenWrt: `medvemodem-<версия>-<архитектура>-<24.10.8|25.12.6>.tar.gz`. Внутри уже находятся и обязательные, и необязательные пакеты; **не требуется устанавливать всё содержимое**.

| Пакет | Назначение | Установка |
| --- | --- | --- |
| `medvemodem` | Демон, CLI/TUI, управление модемами | **Обязательно** |
| `luci-app-medvemodem` | Веб-интерфейс LuCI | **Обязательно для работы через LuCI**, устанавливать той же версии, что и движок |
| `medvemodem-bot` + `luci-app-medvemodem-bot` | Telegram-бот и его интерфейс | По желанию, **оба пакета вместе**, согласованные с движком |
| `medvemodem-lpac` и необходимые APDU-компоненты | Дополнительные операции eSIM | Только если нужны и поддерживаются оборудованием; не устанавливать все транспорты подряд |
| `QModem core` | Альтернативный исполнитель для совместимых модемов | **Не обязателен для MedveModem**; ставить отдельно только для выбранного управления через QModem |
| ModemManager, `uqmi`/`umbim`, драйверы, `qmi-utils` | Зависимости и конкретные способы связи | По потребности модема; часть зависимостей автоматически подтянет `opkg`/`apk` из репозиториев прошивки |

**Два независимых вида релизов.** Выпуски MedveModem (`v0.16.0-alpha1-r1`, будущий `v0.16.0-alpha1-r2` и т. д.) содержат архивы с перечисленными пакетами и `SHA256SUMS`. В рамках одного выпуска выбирайте только свой архив, а не шесть сразу. Постоянный выпуск [QModem `qmodem-3.3.0_p20261108-r1`](https://github.com/Medvedolog/medvemodem/releases/tag/qmodem-3.3.0_p20261108-r1) содержит **шесть других архивов** (архитектуры `aarch64_cortex-a53`, `aarch64_generic`, `x86_64` × линии OpenWrt `24.10`/`25.12`) и свой `SHA256SUMS`. Его архивы имеют имя `qmodem-3.3.0_p20261108-<архитектура>-<24.10|25.12>.tar.gz`. QModem **не входит в обязательную установку и не включает чужой LuCI**.

**Проверка и обновления.** Перед ручной установкой сверяйте SHA256 скачанного архива с `SHA256SUMS` того же релиза (`sha256sum имя-файла.tar.gz`). Раздел обновлений MedveModem в LuCI проверяет GitHub Releases, устанавливает движок и его LuCI **вместе**, а Telegram-бот и его LuCI обновляет **только если бот уже установлен**. Отсутствующий бот не устанавливается обновлением автоматически. Режим `bench` выбирает стендовые релизы `bench-v*`, режим `release` — релизы с тегами `v*`; для обычных `v0.16.0-alpha1-r*` нужен **канал release**. Это механизм **проверки и запуска обновления пользователем**, не обещание фоновой установки без подтверждения. QModem имеет **отдельную** установку/обновление из панели компонентов: она использует закреплённый URL конкретной сборки и `SHA256SUMS`, а не произвольно последний QModem из GitHub. Версии, доступные для установки, зависят от версии самого MedveModem.

## 2. Установка основного пакета

Передайте **один выбранный** архив, указав настоящее имя скачанного файла:

```sh
# На компьютере, в каталоге со скачанным архивом:
scp ./имя_скачанного_архива.tar.gz root@192.168.1.1:/tmp/
```

На роутере:

```sh
mkdir -p /tmp/medvemodem-install
cd /tmp/medvemodem-install
# Замените имя файла на название переданного архива:
tar -xzf /tmp/имя_скачанного_архива.tar.gz
ls -l *.apk *.ipk 2>/dev/null
```

Выберите **один** вариант для своей системы:

```sh
# OpenWrt 25.12 / apk:
apk update
apk add --allow-untrusted ./medvemodem-0*.apk ./luci-app-medvemodem-*.apk

# ИЛИ OpenWrt 24.10 / opkg:
opkg update
opkg install ./medvemodem_*.ipk ./luci-app-medvemodem_*.ipk
```

Не запускайте оба блока подряд и не ставьте по маске всё из каталога: дополнительные пакеты могут включать опциональные транспорты eSIM. Движок и LuCI должны быть **одной версии**. Если пакетный менеджер сообщает об ошибке, остановитесь и сохраните текст ошибки.

## 3. Дополнительные компоненты

**Из LuCI, без SSH.** После установки движка зайдите в «Модем» → «MedveModem» → «Настройки» → «Диагностика и
компоненты». Карточка «Драйверы и ModemManager» показывает, что из нужного модемам уже стоит, и ставит недостающее
кнопкой из лент самого роутера: ModemManager, драйверы ядра (`option`, `qmi_wwan`, `cdc_mbim`, `cdc_ncm`, `cdc_ether`,
`rndis_host` и другие), `umbim` и `uqmi` для прямого подключения, `usb-modeswitch`, `qmi-utils`. Сначала идёт пробный
прогон: если чего-то нет в лентах (модули ядра снапшота, отключённая лента), ничего не ставится, а журнал говорит, чего
не хватило. Работающий ModemManager при этом не перезапускается. Там же карточка «QModem» ставит ядро QModem из
архива стендовой сборки. Те же действия можно сделать и вручную по SSH (`apk add …` / `opkg install …`).

Telegram-бот поставляется как **два отдельных пакета внутри выбранного архива MedveModem**: `medvemodem-bot` и `luci-app-medvemodem-bot` (версии должны соответствовать движку). eSIM уже поддерживает **обнаружение, чтение EID и профилей, переключение между ранее записанными профилями**: на странице модема откройте «Диагностика» → «Проверить eSIM», затем вкладку «eSIM». Новые профили на встроенную eUICC или карту UICC/9eSIM **до Alpha 2 загружайте через совместимый телефон** (приложение карты, EasyEUICC/OpenEUICC на Android), а не через MedveModem; компоненты `medvemodem-lpac`/APDU-транспорта выбирайте под модем. QModem ставится отдельно при выбранном способе управления или из интерфейса компонентов. Не заменяйте системный `lpac` случайным пакетом другого проекта.

## 4. Проверка и обновление

```sh
/etc/init.d/medvemodemd status
ubus call medvemodem status
logread -e medvemodem
```

LuCI: «Модем» → «MedveModem». После изменения файлов LuCI при необходимости перезапустите `rpcd` и обновите вкладку браузера; установка пакета LuCI выполняет это в `postinst` и может завершить текущую веб-сессию.

Обновление — тем же способом, но новым согласованным набором пакетов. Настройки обычно сохраняются, однако восстановление сети через модем во время перезапуска демона **может занять время**. Перед обновлением сохраните `/etc/config/medvemodem` и убедитесь в наличии резервного доступа.

Удаление: `apk del luci-app-medvemodem medvemodem` либо `opkg remove luci-app-medvemodem medvemodem`. Не удаляйте другие установленные менеджеры и сетевые интерфейсы автоматически.

Автоматическое восстановление можно отключить отдельно:

```sh
uci set medvemodem.core.auto_recovery='0'
uci commit medvemodem
/etc/init.d/medvemodemd restart
```

## 5. Если модем не появился

Соберите `medvemodem diag quick`, вывод `ubus call medvemodem status`, `logread -e medvemodem`, `logread -e ModemManager` и точную версию прошивки. Не публикуйте неотредактированные журналы с идентификаторами SIM или паролями. Для полевой диагностики — BENCH и [база модемов](modem-zoo/README.md).
