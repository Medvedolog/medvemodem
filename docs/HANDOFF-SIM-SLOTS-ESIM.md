# HANDOFF: независимая диагностика SIM-слотов и расширение eSIM

**Статус:** согласованное техническое задание, **не реализация**. 17.11.2026.
**Область:** MedveModem Alpha 2 / последующие ревизии, OpenWrt 24.10 (opkg) и 25.12 (apk), несколько модемов на одном роутере.
**Приоритет:** P1 — безопасное обнаружение слотов/eUICC; P2 — полное управление профилями SGP.22 и HTTP/TLS совместимость.
**Безусловное решение владельца проекта:** переключать физические SIM/eSIM-слоты **исключительно вручную, по явно подтверждённому действию администратора**. Автоматический выбор или переключение слота при обнаружении, диагностике, обновлении и восстановлении запрещены.

## 0. Существующая реализация (не выдавать за новое)

- `src/mmgr.c` уже получает `sim-slots` и `primary-sim-slot` из ModemManager. Символ `/` означает отсутствие карты; движок строит `modemmanager.sim_slots[]` как массив признаков присутствия.
- `src/mgr_sim.c` имеет `sim_slot` через `mmcli --set-primary-sim-slot` только когда владельцем является ModemManager; общий код PIN/PUK расположен там же.
- `src/mgr_esim.c`, `src/esim.c`, `src/esim_apdu.c` и `files/usr/libexec/medvemodem/esim-lpac` обеспечивают асинхронные проверки lpac, APDU и EID с арендой порта и завершением группы процессов по тайм-ауту. Пределы сейчас: probe 10 с, действие 45 с, поиск AT-порта eUICC 60 с, до четырёх eSIM jobs.
- Текущая Alpha 1 обнаруживает eUICC, читает EID/список профилей и позволяет вручную включить существующий профиль. **Загрузка, удаление, отключение, изменение nickname, уведомления SGP.22 — планируемые возможности, не готовые команды Alpha 1.**
- LuCI уже умеет показывать наличие SIM в неактивном слоте **только если данные дал ModemManager**; универсальной QMI/UIM/MBIM/AT-диагностики слотов нет.
- Любое изменение документированного API согласовать с `docs/UBUS-API.md` и тестами; не ломать текущие поля и существующие вызовы.

## 1. Модуль `mgr_simslot.c` / `mgr_simslot.h`

Перенести логику чтения и безопасного переключения слотов из `mgr_sim.c` в `src/mgr_simslot.c`, оставив в `mgr_sim.c` PIN/PUK и SIM-операции, не связанные со слотом. `mmgr.c` остаётся поставщиком данных ModemManager, новый модуль нормализует результаты и выбирает источник. Добавить в `Makefile` явную компиляцию нового модуля, декларации, регистрации ubus и тесты. Разделить `sim_slots` (чтение) и `sim_slot` (существующее ручное изменение).

### Нормализованное состояние

Каждому физическому слоту дать `id`, `label`, `kind` (`physical|euicc|unknown`), `active` (bool), `presence` (`present|empty|unknown`), `source` (`modemmanager|qmi_uim|mbim|vendor_at|cache`), `confidence` (`confirmed|inferred|unknown`), `age_ms`, `reason` при отказе. `unknown` — **не** `present`. Не выставлять `present` только по доступности `AT+QUIMSLOT?`, `AT^switch_slot?`, `AT!UIMS?` или количеству слотов.

Различать `slot_exists`, `card_present`, `slot_active`, `euicc_capable`, `euicc_present`, `euicc_accessible`. `euicc_capable` по VID:PID/модели — подсказка, не физическое подтверждение. `euicc_present` можно подтвердить типом eUICC в QMI/MBIM, даже когда слот неактивен. `euicc_accessible` требует ответа чипа по APDU (EID/ISD-R). Не интерпретировать `unknown` как отсутствие eUICC.

**Пример API (черновик, до реализации не считать публичным контрактом):**
```json
{
  "device_id": "<device-id>",
  "generation": 12,
  "source": "qmi_uim",
  "state": "ok",
  "slots": [
    {"id": 1, "label": "SIM1", "kind": "physical", "active": true,
     "presence": "present", "confidence": "confirmed"},
    {"id": 2, "label": "eSIM", "kind": "euicc", "active": false,
     "presence": "present", "confidence": "confirmed"}
  ],
  "euicc": {"capable": true, "present": "present", "accessible": "unknown"}
}
```

`device_id` и USB attachment generation обязательны; смена поколения отменяет результаты старых jobs. Для отсутствующих возможностей возвращать честные `unknown` + `reason`. Поля ICCID/EID/IMSI никогда не логировать и не включать в поддержку без обезличивания.

### Приоритет источников

1. **ModemManager:** `sim-slots`, `primary-sim-slot`, пути SIM (`/` = пустой); тип карты из свойств SIM при наличии. Дубликаты названий двух физических слотов заменять на SIM1/SIM2. Если MM сообщает только один слот или ошибку, возможен fallback **лишь при свободном и разрешённом транспорте**.
2. **QMI UIM:** `--uim-get-slot-status` с `Card status`, `Slot status`, `Is eUICC`; использовать действующий proxy/владельца канала. Никаких прямых конкурирующих клиентов и утечек QMI client IDs.
3. **MBIM:** `--ms-query-device-slot-mappings` и `--ms-query-slot-info-status`, точное соответствие `state-empty`, `inactive-esim`, `active-esim`. Совместимый `mbim-proxy` только при разрешённом владельце; `umbim`-занятый канал не открывать и не нарушать соединение.
4. **Vendor AT:** профильные read-only команды: Fibocom `AT+GTDUALSIM?`/`AT+SIMTYPE?`, Foxconn/Thales `AT^switch_slot?` или `AT+SWITCH_SLOT?`, Quectel `AT+QUIMSLOT?`, Sierra `AT!UIMS?`, Telit `AT#SIMDET?`/`AT#QSS?`, Compal `AT+CEISWITCHSIM?`. Запрашивать только у точного физического модема, через арбитраж и lease AT-порта; не трогать tty dialer; профильные правила `none` для модемов с ложными виртуальными слотами.
5. **Кеш:** при занятости порта возвращать последнее подтверждённое состояние с `stale`/возрастом; не превращать старое значение в свежий факт.

**Особые случаи:** HiLink без физического dual-SIM не должен получать фиктивный слот eSIM по одному ответу AT. У отдельных SDX55/SDX62 eUICC может находиться во втором неактивном слоте, у некоторых модемов только активный слот доступен по AT — `presence=unknown` и предлагается ручная проверка. Состояние `inactive-esim` не равно `active-esim` (строгий разбор, без подстроки). Не считать второй слот пустым по недоступности APDU из SIM1.

## 2. Защита главного демона и соединения

- **Запрет синхронного блокирующего I/O в главном uloop/ubus обработчике.** Каждая аппаратная проверка — отдельный supervised child/process group, nonblocking pipe + `uloop_process`/`uloop_fd` и `uloop_timeout`. Штатно отвечать из кеша и запускать refresh асинхронно.
- Бюджет чтения одного транспорта 5–10 с, общий бюджет диагностики одного модема **не более 15 с**; по истечении — kill **только группы процесса этой диагностики**, ответ `unknown`/timeout, сохранение прежнего подтверждённого кеша. Это проектные пределы и могут уточняться стендом; eSIM/lpac операции имеют свои бюджеты.
- Per-device jobs, ограничение параллельности и queue, deduplication запроса, cooldown после timeout; точно не открывать занятые MM, QModem, netifd/umbim ресурсы. Lease с generation, строгий match устройства для WDM/tty, очищать/инвалидировать кеш при re-enumeration и ручном switch; результаты старого поколения игнорировать.
- Положительный eUICC cache сохранять между запросами пока идентичность устройства достоверна; негативный вывод на ограниченное время (например 600 с) и только после действительно успешного атомарного hardware probe. Busy, timeout, port error, отсутствующий lpac или сломанный HTTP/сертификат **не означают** `absent`. Отдельные кеши `capability`, `slot status`, `eUICC probe`, `profile list`, каждый с `age`, `source`, `last_success`; refresh в фоне с TTL, error backoff, запрет массовой перепроверки на каждую загрузку LuCI.
- APDU: для AT искать порт двухфазным `AT+CCHO` ISD-R, строго привязывать его к модему и USB generation; закрывать собственные логические каналы `AT+CCHC`. Учесть зависшие/утёкшие APDU каналы: ограниченный безопасный cleanup только при владении каналом и подтверждённом контексте, без чужих сессий; для QMI/MBIM закрывать только известные собственные каналы. На Sierra и других несовместимых AT-CCHO модемах не производить опасный пробный доступ.
- Никаких `reset`, `CFUN`, inhibit ModemManager, kill proxy, ifdown/ifup, MBIM executor remapping в **фоновой read-only диагностике**. Если безопасного транспорта нет — `unavailable/busy`, предложение ручного действия, интернет не трогать. Не использовать прямые WDM вызовы, которые могут вызвать MBIM CLOSE или конфликт с владельцем.
- Проверки на 5 физических модемах и стендах: быстрый idle, блокированный AT, поломанный proxy, выдёргивание USB во время операции, несколько одинаковых tty-номеров, чтение неактивной eUICC, MM/QModem/netifd ownership, stale response, SIGKILL зависшего дочернего процесса. Главный `medvemodemd` отвечает на `status`/`devices` в пределах привычного времени даже при hang.

## 3. Только ручное переключение слота: UI и сервер

- **Любое переключение SIM1/SIM2/eSIM — только явная кнопка и подтверждение администратором** с предупреждением о временном обрыве интернета, потере регистрации, возможном переназначении USB портов и необходимости redial. Никакой автоматической смены ради поиска EID/профилей, восстановления доступности eUICC, скачивания профиля, применения настроек, startup, cron, диагностики, fallback и автообновления.
- Для модели, где тип второго слота известен, но он неактивен, LuCI показывает рекомендацию: «Обнаружена eSIM во втором слоте. Для чтения EID и профилей выберите SIM2/eSIM вручную. Соединение временно прервётся». Отдельное `unknown` показывает «Наличие SIM не удалось проверить», а не «Пусто».
- Все переключения проверять в серверном коде: владелец, тип слота, generation, ACL, lease, занятость и безопасный транспорт; после нажатия — bounded switch, подтверждение фактического активного слота, корректное возобновление только канала данного модема, сброс связанных кешей и повторный опрос. Если не удалось — состояние ошибки, без цепочки автоматических смен/переключения назад.
- LuCI отображает `SIM1 · активна · установлена`, `SIM2/eSIM · неактивна · установлена/пуста/неизвестно`, источник и возраст результата в подробном режиме; отдельная кнопка «Обновить данные» не меняет слот. При неизвестном типе не подменять eSIM просто из-за модельной подсказки.
- Переключение **профиля внутри уже выбранной eUICC** — отдельная явная операция Alpha 1, её текущий смысл сохранить; не связывать её с автоматической сменой физического SIM-слота.

## 4. SGP.22 / lpac: полнота операций и надёжность

На базе `mgr_esim.c` и собственного lpac backend, не создавать конкурирующий контроллер модема:

1. Подтверждённые `chip`/EID, `profiles`, `enable` сохранить, расширять до `disable`, `delete`, `nickname`, `download`, `notifications` и обработки очереди уведомлений. Функции уровня Alpha 2 вводить по отдельности с тестами и ACL.
2. Для скачивания: асинхронный job с ID, статусом, прогрессом, bounded timeout/watchdog (целевой общий бюджет до 10 минут), per-eUICC mutex, отменой, ограниченными повторными попытками по классификации ошибок; не повторять операции, которые сервер явно отклонил; после неопределённого окончания проверять наличие ICCID, чтобы не дублировать установку.
3. Поддержать AT `stdio` bridge и локальную ES9+ HTTP обработку, корректное чтение APDU `CCHO/CGLA/CCHC`, включая bare numeric CCHO на отдельных Fibocom и `CGLA` длину в HEX-символах согласно прошивке. Логические каналы и выходные файлы аккуратно закрывать/чистить после abort, без записи APDU-секретов в логи.
4. На QMI/MBIM корректно определять тип control device по sysfs, подбирать физический target исключительно в рамках данного модема; optional lpac drivers и зависимости объяснять в настройках. Согласовывать executor/APDU slot с текущим активным слотом; **не переназначать MBIM mapping автоматически даже если lpac умеет это делать**, не отключать связь для обычного чтения. При необходимости показать ручную рекомендацию и кнопку отдельного явного действия.
5. Учитывать несовместимые lpac layouts и отсутствующие/сломанные HTTP/APDU плагины, не трактовать `euicc_init` при недоступном transport как отсутствие чипа; показывать диагностику `backend`, `driver`, `node`, `reason` с редактированием личных идентификаторов.
6. Для операций, которым действительно нужен временный эксклюзивный доступ (например, download), сначала оценивать наличие другого WAN и необходимость текущего канала для достижения SM-DP+. Временно освободить uplink / выполнить MM inhibit **только после отдельного явного согласия администратора** с оценкой влияния и гарантированным восстановлением по bounded watchdog; если это единственный интернет — не отключать его молча. Такие процедуры не являются «автоматическим переключением SIM-слотов».
7. После явного switch профиля запросить новое состояние, предупредить о требуемой перерегистрации/рестарте; запретить фоновый hard reset от одного лишь просмотра страницы. Сложные восстановительные действия только по согласованной пользовательской операции.

## 5. TLS/сертификаты для GSMA ES9+ в условиях ограниченной инфраструктуры

**Требование эксплуатации:** доступность SGP.22 и SM-DP+ должна сохраняться при несовместимых системных CA-хранилищах, криптобэкендах и ограничениях распространения сертификатов. Ошибка цепочки GSMA CI при mbedTLS или отсутствие части нужных CA не должны маскироваться как `no euicc` и не должны неизбежно блокировать загрузку.

Порядок реализации:

1. Сначала проверять соединение с использованием стандартного TLS и нормальной верификации сертификатов. Поддержать отдельный CA bundle с актуальными сертификатами GSMA CI; если системный `curl`/mbedTLS отвергает нужные расширения/X.509 или RSA-PSS, предложить совместимый альтернативный HTTP transport на базе OpenSSL/GNU wget (или эквивалентный) и использовать его **с проверкой сертификата**.
2. Если все проверенные транспорты недоступны именно из-за проверки цепочки, предусмотреть **явно настраиваемый аварийный fallback** с временным отключением TLS chain verification только для конкретного запроса ES9+ при информированном подтверждении администратора. Отдельный видимый статус «TLS verification disabled for this request»; не глобальный флаг, не долговременный скрытый режим, не автоматическое отключение для произвольных endpoint. Сохранять проверку DNS/endpoint и предупреждать о MITM и рисках перехвата метаданных. Не отключать проверку после обычных сетевых ошибок, HTTP 4xx/5xx или ошибки формата ответа.
3. Для ограниченных сетей разрешить ручную конфигурацию DNS, HTTP proxy/tunnel и доверенных CA; доступность SM-DP+ проверять независимо от доступности eUICC и не выводить «чип отсутствует» при TLS/DNS timeout.
4. Вся ES9+ передача: лимиты времени и размера, redaction activation code / matching ID, отсутствие секретов в stdout, shell argv и диагностических экспортах; скрывать чувствительные подробности от неавторизованных пользователей.
5. Отдельно тестировать корневые сертификаты GSMA, TLS backend mbedTLS/OpenSSL, цепочки с критическими X.509 extensions, RSA-PSS, gzip вне заголовка, ответ 200 с `functionExecutionStatus=Failed`, обрыв тела, повторные попытки. **Ослабление TLS — доступная аварийная опция, а не обязательный или автоматический стандартный путь.**

## 6. Очерёдность внедрения и приёмка

**Этап A — только чтение SIM slots (P1):** выделить модуль, JSON/ubus контракт, MM + QMI/MBIM + profile-aware AT, cache/async/timeouts, accurate `presence` и eUICC present without APDU. Принять после симуляций отсутствующего/занятого слота и аппаратных испытаний без потери связи.

**Этап B — LuCI/ручное переключение (P1):** две карточки, индикаторы, подпись eSIM по подтверждённым данным, объяснимый unknown, кнопка переключения с подтверждением, связь с существующим `sim_slot`; read-only API не имеет побочных эффектов. Стабильность существующего Alpha 1 eSIM не ухудшена.

**Этап C — расширенное eSIM (P2):** универсальные безопасные backend/transport/slot detection, правильная обработка неактивной eUICC, диалоги с рекомендацией ручной смены слота, очистка APDU каналов и отказоустойчивость. Только после этого полноценный SGP.22 download/delete/notifications и механизм совместимости GSMA TLS.

**Критерии приёмки (все обязательны):**
- Вторая SIM физически отсутствует → `empty` только при достоверном ответе; при AT-only ответе о выборе слота → `unknown`.
- Неактивная eUICC в SIM2 детектируется через QMI/MBIM без смены active SIM, а EID при недоступности честно остаётся `unknown`.
- Ни открытие LuCI, ни диагностика, ни CI, ни восстановление не переключают слот, не меняют MBIM mapping, не вызывают `CFUN/reset`, не рвут интернет.
- Если external probe повис, основной `medvemodemd` продолжает отвечать, убит только процесс probe, его тайм-аут/кеш корректен.
- На роутере с несколькими модемами SIM, WDM и tty чужого устройства не трогаются; USB re-enumeration не подменяет старые результаты новыми.
- Отображаются `present/empty/unknown` и реальные причины; eSIM capability не выдаётся за присутствие.
- Download/HTTP ошибки TLS, сети или транспорта не обозначаются `euicc_absent`. Подтверждённый аварийный TLS fallback работает только для выбранного ES9+ запроса, без глобального ослабления безопасности.
- Тесты 24.10/opkg и 25.12/apk, все целевые архитектуры; профильные матрицы, тесты парсеров и fault injection.

**Не включать выполнение этого задания в ветку опубликованной Alpha 1 r2 без самостоятельной сборки/релиза и проверки на железе.**
