# MedveModem: настройка при доступе только к доменам из белого списка оператора

Оператор может ограничить мобильный интернет так, что открываются только отдельные разрешённые сайты и сервисы. В этом руководстве описано, как определить такой режим в MedveModem, проверить доступность сайтов через каждый модем, просмотреть состояние соединения и разобраться в причинах ограниченного доступа.

Проверено по коду MedveModem 17 ноября 2026 года. Доступность конкретных доменов зависит от оператора, региона и времени проверки.

## 1. Как понять, что доступ ограничен белым списком

Типичная ситуация: модем зарегистрирован в сети и передача данных установлена, но большинство сайтов не открывается, а несколько разрешённых оператором доменов продолжают работать.

Похожую картину могут давать блокировка отдельных сайтов, ошибки DNS, неоплаченный тариф, проблемы с маршрутизацией или соединением. Поэтому MedveModem сравнивает доступность двух групп адресов и показывает **«Ограниченный доступ»**, а не утверждает, что оператор точно включил белый список.

Если не открываются даже домены из разрешённой группы, сначала проверьте регистрацию SIM, APN, баланс, DNS и саму передачу данных. Переключать слоты SIM или перезагружать модем из-за одного неудачного теста не нужно.

## 2. Возможности диагностики MedveModem

| Возможность | Где |
|---|---|
| Показывать, когда основная группа проверочных адресов недоступна, а разрешённые адреса отвечают | Главная → состояние канала; «Белые списки» → «Сейчас» |
| Проверять открытие сайтов отдельно через каждый модем | «Белые списки» → «Проверка сервисов» |
| Настраивать контрольные адреса двух групп | «Настройки» → «Проверка соединения»; «Белые списки» → «Как определяется белый список» |
| Не перезапускать исправный модем при обнаружении только ограниченного доступа | Встроенная диагностика и восстановление |
| Сообщать об ограниченном доступе через SMS и Telegram, если настроена доставка | «Белые списки» → «Уведомления» |

MedveModem не получает от оператора официальный признак включённого белого списка. Статус `limited` — результат собственных проверок доступности.

## 3. Первичная настройка

1. Установите MedveModem и LuCI совместимой версии с зависимостями; проверьте, что модем зарегистрирован в сети, получил сессию и видит интернет. Смотрите [установку](INSTALL.md) и [зависимости APK/OPKG](DEPENDENCIES.md).
2. Откройте LuCI: **«Модем» → «MedveModem» → «Белые списки»** (пункт отдельный, не ищите все его настройки в общей странице «Настройки»).
3. В блоке **«Сейчас»** посмотрите каждый канал и его роль: основной, резервный, полный интернет, ограниченный доступ или отсутствие ответа. При сомнениях проверьте каждый модем отдельно.
4. В **«Проверке сервисов»** выберите модем либо **«Все каналы»**. Результат — таблица «сервис × канал», показывающая фактический ответ *на момент проверки*. Для одного канала обычно требуется около 10 секунд и менее 1 МБ; при выборе всех проверка последовательная по каналам.
5. Сравните результаты проверки по каналам. Различия между операторами или сетями помогают определить, относится ли проблема к конкретному подключению.
6. При необходимости настройте уведомления. Не меняйте настройки удалённого роутера без возможности восстановить доступ.

### Пример интерпретации

- Google/GitHub не открываются, но Яндекс/VK работают, модем зарегистрирован и сессия поднята → **подозрение на ограничение мобильного интернета**. Прежде чем делать вывод, исключите обычные блокировки сайтов, проблемы DNS и маршрутов.
- Не отвечает ни основная, ни ограниченная группа, модем без IP/регистрации → сначала проверить SIM, APN, оплату, качество сигнала, питание и сетевую сессию.
- Один зарубежный ресурс не работает, прочие ресурсы основной группы работают → скорее адресная блокировка или ошибка сервиса, **не** доказательство whitelist.
- SIM после возвращения из международного роуминга или длительного отключения не получает обычный доступ → уточните у оператора «охлаждение» и процедуру восстановления, не пытайтесь лечить его сменой DNS.

## 4. Как определяется ограничение доступа

В `src/medvemodemd.c` для каждого пути запускаются **привязанные к конкретному сетевому устройству** TCP-проверки (`SO_BINDTODEVICE`).

- `core.reach_target`: **основная группа**. По умолчанию `1.1.1.1:443 8.8.8.8:443`.
- `core.reach_restricted`: **вторая группа**, ресурсы, которые часто доступны при ограничениях. По умолчанию `77.88.55.242:443 87.240.132.72:443` (Яндекс/VK). Значение `none` отключает эту проверку.
- Если первая группа не отвечает, а вторая отвечает, состояние канала становится **`limited` («Ограниченный доступ»)** после подтверждений/гистерезиса. Это **не юридическое или техническое подтверждение белого списка**.
- Проверка использует TCP, а на порту 443 дополнительно ограниченный TLS handshake, чтобы не спутать сайт с ответом страницы оператора при отсутствии оплаты. Слишком быстрый ответ самого HiLink модема также фильтруется.
- Обычно основной канал проверяется примерно **раз в минуту**, резервные — примерно **раз в пять минут**; при изменении/переключении или включённом резервировании проверки могут быть чаще. Реакция сглажена повторными измерениями, нет мгновенного вывода из одной ошибки.
- При `limited` движок **не считает модем неисправным** и не должен запускать разрушительные USB/reset-действия только по этому признаку. Если есть полноценный резерв — он предпочтительнее.

Проверка TCP/TLS не гарантирует, что весь сайт или приложение будет работать.

### Настройка контрольных адресов в LuCI

В обычных **«Настройках» → «Проверка соединения»** задайте **«Основные адреса»**. В разделе **«Белые списки» → «Как определяется белый список»** задайте **«Адреса белого списка»**. При нормальной работе обычно оставляйте значения по умолчанию.

Вводятся адреса вида `IP:порт` или совместимые доменные имена с портом, разделённые пробелами. Используйте как минимум два независимых, проверяемых endpoint. При выборе своих целей учитывайте, что одно доменное имя, геоблокировка или DNS-сбой способны создать ложный вывод. Вторая группа должна отвечать из сети данного оператора; не вводите произвольные IP, лишь предположительно входящие в разрешённый перечень.

Для опытных пользователей в конфигурации `/etc/config/medvemodem` используются параметры `core.reach_target`, `core.reach_restricted`, а также `core.reach_tls`. Редактировать UCI имеет смысл только после сохранения резервной копии, иначе можно испортить всю диагностику и результаты определения доступности.

## 5. Проверка сайтов через отдельные каналы

На странице **«Белые списки» → «Проверка сервисов»** используйте кнопку **«Проверить сервисы»**. Реализация `/usr/libexec/medvemodem/netcheck` проверяет сервисы **в параллель по одному выбранному интерфейсу**, до 8 секунд на сайт, с `curl --interface if!<device>` и проверкой TLS-сертификата. Для нескольких каналов LuCI последовательно проверяет каждый.

Текущие группы в `/usr/share/medvemodem/netcheck.list`:

- `open`: Google, GitHub, Wikipedia, Cloudflare, Microsoft — условные общие контрольные точки. Один заблокированный сайт сам по себе не указывает на whitelist.
- `known`: Telegram, YouTube, WhatsApp, Discord, Claude, ChatGPT — **не использовать их недоступность как признак whitelist**: ресурсы могут быть заблокированы или отказывать по собственным правилам.
- `list`: Яндекс, VK, Wildberries и сайты МТС, T2, МегаФона, Билайна — вероятные контрольные точки для сопоставления с основной группой.

Статусы: `ok` (HTTP-ответ), `blocked` (403/451), `timeout`, `dns`, `refused`, `reset`, `tls`, `cert`, `tunnel`, `other`. `tunnel` означает, что результат может зависеть от действующей на роутере DNS-маршрутизации; он не подходит для оценки прямой доступности через модем. `cert` указывает на ошибку проверки сертификата.

**При ошибках `dns` проверьте** DNS роутера, провайдера и программы маршрутизации. В некоторых мобильных ограничениях отвечают резолверы Яндекса `77.88.8.8`/`77.88.8.1`, но доступность не гарантирована. Не меняйте глобальный DNS только по одной неудачной проверке.

**При `tunnel`** проверяйте только корректность диагностики: статус отражает влияние текущей DNS-маршрутизации, а не обязательно прямую доступность сайта.

## 6. Уведомления

- **SMS:** в «Белые списки» → «Уведомления» включите оповещение «Только белый список», задайте длительность события (по умолчанию **15 минут**) и настройте общие SMS-адресаты в «Настройки» → «Уведомления». SMS может работать при недоступности пакетной передачи, если голос/SMS сеть доступна и тариф позволяет.
- **Telegram-бот:** при настроенном боте можно получать сообщения об ограниченном доступе и восстановлении. При отсутствии доступа к Telegram уведомление может не доставиться.


## 7. Типовые ситуации

| Ситуация | Что проверить |
|---|---|
| Открываются только несколько разрешённых сайтов | Проверку двух групп адресов, состояние `limited`, результат тестирования сервисов |
| Один сайт не открывается, остальные работают | DNS, ответ сервиса и доступность его домена; одного отказа недостаточно для диагноза |
| Не открывается ни один сайт | Регистрацию SIM, APN, баланс, состояние сессии, DNS и качество сигнала |
| Ограничение затрагивает только одного оператора | Результаты проверки по каждому из имеющихся соединений |
| Состояние меняется в течение дня | Время проверок и уведомления; сравнить несколько последовательных результатов |

## 8. Просмотр состояния и диагностика

Для просмотра по SSH (ничего не изменяет):

```sh
ubus call medvemodem uplink
ubus call medvemodem wlmode '{"action":"status"}'
uci -q show medvemodem | grep -E 'reach_|wlmode'
logread | grep -iE 'medvemodem|limited|wlmode'
```

Если режим управления туннелями уже был настроен ранее, его текущее состояние можно посмотреть в соответствующей карточке LuCI. Этот документ не содержит инструкций по его включению.

При обращении в поддержку приложите обезличенный диагностический отчёт, модель модема, оператора и время проверки. Не публикуйте IMEI, IMSI, ICCID, номера, пароли и токены.

## 9. Ограничения

Определение белых списков носит вероятностный характер. Ошибки DNS, TLS, тарифа, маршрутизации и отдельных сайтов могут создавать такую же картину. MedveModem не получает от оператора полный перечень разрешённых доменов и не гарантирует их доступность.

Проверки показывают состояние выбранного подключения на момент измерения. Список доступных ресурсов может изменяться независимо от настроек роутера.
