Подробное руководство: основной текст составлен на базе r151; **заголовок и навигация сверены с исходниками
0.15.0-r197 (16.11.2026), но не каждая страница повторно испытана в браузере**. Новые функции и ограничения

[INSTALL](INSTALL.md), краткая памятка — [USER-GUIDE](USER-GUIDE.md). ТЗ содержит

бот говорит на языке, выбранном в его настройках.

## 1. Что это и из чего состоит

MedveModem — менеджер USB-модемов для OpenWrt 24.10 и 25.12. Он находит модем, решает, кто им управляет, поднимает
подключение, проверяет, что через модем действительно есть интернет, переключает роутер на резервный канал при сбое и
сам чинит модем по ступеням — от переподключения сессии до перезапуска по USB. К модемам относятся и телефоны в режиме
USB-модема, и «свистки»-роутеры со своим веб-интерфейсом (Huawei HiLink, ZTE, МегаФон M150-4, UFI).

| Пакет | Что внутри |
|---|---|
| `medvemodem` | движок `medvemodemd` (C), консоль `medvemodem` (CLI и TUI), помощники в `/usr/libexec/medvemodem/`, профили модемов в `/usr/share/medvemodem/profiles`, база APN |
| `luci-app-medvemodem` | страницы LuCI «Модем → MedveModem» на английском и русском, строка в «Состояние → Обзор», страница протокола для «Сеть → Интерфейсы» |
| `medvemodem-bot` | Telegram-бот (ucode) и его служба ubus `medvemodem.bot`, `medvemodem.bot.config` |
| `luci-app-medvemodem-bot` | страницы LuCI «Telegram-бот»: «Обзор», «Мастер настройки», «Настройки» |
| `medvemodem-lpac`, `medvemodem-lpac-uqmi` | eSIM (lpac): чтение и переключение профилей, по желанию; ставится и из «Диагностика и компоненты» |

Движок и LuCI одной версии ставятся только вместе: страница сверяет свою версию с движком и при расхождении просит
обновить страницу.

## 2. Как это устроено

### 2.1. Слои

```
 LuCI · консоль (CLI, TUI) · Telegram-бот        клиенты: только через ubus
                   │
          ubus-объект «medvemodem»                 одно API для всех
                   │
   medvemodemd — один процесс на uloop
     ядро: реестр устройств, владение, подключения, аренда AT-порта, проверка связи,
           автопереключение каналов, DNS, восстановление
     модули mgr_*: SMS, радио, сигнал, веб модема, лимиты трафика, USB-дерево, SIM, eSIM,
           история AT, режим белых списков, сбои роутера и другие
     отдельные процессы: AT-задания, чтение ModemManager, пересылка SMS, lpac, помощники
           TTL, маршрутов, веба, спидтеста, режима белых списков
                   │
   исполнитель модема — ровно один:
     сам движок (AT + QMI/MBIM/NCM через netifd) · ModemManager · QModem · веб модема
```

Клиенты ничего не делают с модемом сами: и LuCI, и бот, и консоль просят движок, а движок решает, можно ли, и
ставит задание в очередь. Поэтому всё, что видно на странице, видно и в боте, и в `medvemodem show <id>`.

### 2.2. Опознание и владелец

- **Модем узнаётся** по профилю: VID:PID, классы USB-интерфейсов, драйверы. Профилей больше 80 (`profiles/`): кто
  лучше управляет моделью, AT-диалект, какие порты для чего, особенности («USSD в LTE уводит модем в 3G»), какие
  ступени восстановления безопасны. Модем без своего профиля получает профиль семейства (по производителю или по
  драйверу) и плашку «знает не полностью» с кнопкой отчёта.
- **Один владелец.** У каждого модема ровно один хозяин подключения: ModemManager, QModem, сам движок («MedveModem
  напрямую») или веб модема (HiLink, ZTE и подобные). Остальные к нему не прикасаются. Выбор — по профилю и тому, что
  установлено; поменять можно в карточке «Подключение» → «Кто управляет модемом».
- **Имя и настройки следуют за модемом**: по серийному номеру USB, без него — по хэшу IMEI (сам IMEI не хранится),
  у одинаковых IMEI — по USB-порту. Телефоны (iPhone, Android) — по порту: их серийный номер — личный идентификатор.
- **Поколения.** После переподключения по USB старые результаты отбрасываются: `ttyUSB2` после сброса — не
  обязательно тот же порт того же модема.
- **Заморозка («Приостановка управления»)** — модем не трогает никто: ни движок, ни ModemManager, ни QModem.

### 2.3. AT-порт

Все AT-запросы — SMS, USSD, сигнал, консоль, привязка к соте — идут через движок по очереди («аренда» порта): никто
не открывает tty сам, ответы не перемешиваются. Если AT-порт держит ModemManager или QModem, вкладки AT нет, а
карточка «AT-порт» говорит, кто его занял и что сделать. У Foxconn T99/T77 ModemManager получает только управляющий
порт, AT-порты остаются у движка (правило udev пишется само).

### 2.4. Проверка связи и каналы

- **Проверка связи** идёт строго через интерфейс модема, мимо маршрутов роутера: соединение с несколькими адресами
  («Основные адреса»), для `:443` — с проверкой, что ответил настоящий TLS. Оператор с нулевым балансом, который
  отвечает на любое соединение своей страницей, даёт «нет интернета», а не «работает».
- **Белые списки.** Если открываются только адреса из «Адресов белых списков» (сайты операторов, госуслуги), канал
  получает статус «Доступны только разрешённые сайты» (в боте — «БС»): трафик по возможности уходит на канал с полным
  интернетом. Если интернет при этом идёт через туннель (podkop, forkop, clash), это сказано.
- **Каналы и приоритет.** Каждый модем — канал со своей метрикой маршрута; проводной WAN — тоже канал. Порядок
  задаётся в «Настройки» → «Интернет и резерв» → «Приоритет каналов» или стрелками в таблице каналов на главной;
  метрику можно поправить прямо в таблице. Автопереключение уводит маршрут по умолчанию на следующий живой канал и
  возвращает его, когда первый отвечает снова. MedveModem меняет только метрики своих интерфейсов, сеть целиком не
  перезапускает.
- **Режим белых списков** (с r149): когда оператор включает белые списки, движок сам закрепляет в podkop 0.8 или
  forkop 2 сервер туннеля, который их переживает, и по желанию пускает через туннель всю LAN и сам роутер; когда
  списки сняты — возвращает всё как было (журнал изменений хранится и переживает перезагрузку).

### 2.5. Восстановление

Ступени от мягкой к жёсткой: наблюдение → переподключение сессии → перезапуск управления → радио выкл/вкл →
перезагрузка модема → перепривязка драйвера → переподключение по USB → питание порта. Движок сам проходит
разрешённые профилем ступени и останавливается на первой, после которой интернет вернулся; между попытками растёт
пауза. У модема-роутера (HiLink, ZTE) «радио» — переподключение мобильной сессии через его веб, «перезагрузка» —
команда веба. Подробно — `USER-GUIDE.md` §6, карточка «Восстановление связи» на странице модема.

Любое изменение, которое может оставить без связи (режим сети, диапазоны, привязка к соте, настройки интерфейса),
делается как транзакция: если интернет через модем за отведённое время не вернулся, прежнее возвращается само.

### 2.6. Модемы-роутеры и их веб

У HiLink, ZTE, МегаФон M150-4, UZ801 нет AT-порта для движка: всё — через их собственный веб. Движок входит в веб с
паролем, заданным в MedveModem (по умолчанию пробует заводской `admin`), не чаще раза в 5 минут, и не входит, если в
вебе сидит человек. Читает сигнал, соту, оператора, SMS; по кнопке — данные модема, USSD, режим сети, переподключение,
перезагрузку. Пароль хранится в настройках этого модема (`web_password` в `/etc/config/medvemodem`).

Чтобы открыть веб модема с компьютера, где прокси-клиент уводит `192.168.8.1` в туннель, роутер открывает порт
`808x` и подставляет модему его собственный адрес (`medvemodem-webproxy`). Порт закрывается сам через время.

### 2.7. SMS

SMS читаются тем, кто владеет модемом: ModemManager, AT-порт движка, QModem или веб модема. Когда память модема
заполняется на три четверти, старые входящие переезжают в роутер («SMS в роутере»). С модема ничего не удаляется
само. Пересылка — в Telegram-бот, в ntfy/webhook и SMS-кой на другие номера. Тексты SMS, IMSI и ICCID в журнал не
пишутся.

### 2.8. Бот

Бот — отдельная служба на ucode. Модемы он видит только через ubus движка, к Telegram ходит сам: напрямую, через
найденные на роутере прокси (mixed/SOCKS у podkop, forkop, NetShift, SSClash, nikki), через прокси, заданные
администратором, через другие модемы и аварийные IP. Каждый путь проверяется, удачный запоминается. Подробно —
раздел 9.

## 3. LuCI: общее

Меню: «Модем → MedveModem» → «Модемы», «Настройки», «Telegram-бот». Страница модема открывается из карточки.

- **Уровень «Базовый / Подробный»** (вверху страницы) прячет или показывает инженерные подробности: метрики,
  интерфейсы, исходные записи журнала, AT-консоль. Выбор запоминается в браузере.
- **«Скрыть идентификаторы»** — для скриншотов: IMEI, ICCID, номера, адреса, ссылка на карту заменяются точками.
- **Баннеры сверху** закрываются крестиком; закрытые остаются в журнале событий с кнопкой «Показать снова».
- **Темы.** Страницы работают под Bootstrap, footstrap и Aurora, на телефоне тоже: таблицы складываются в блоки,
  вкладки прокручиваются, кнопки — под палец.
- **Обновление пакета.** Если пакет обновили, пока страница открыта, она скажет «страница обновлена на роутере» и
  загрузит новую версию.

## 4. «Модемы» — главная

Сверху вниз:

- **Плашка состояния**: есть ли интернет, через какой канал, какие резервы по порядку. Сворачивается в одну строку.
  Если интернета нет через основной канал, а другой работает и переключение выключено — так и сказано, с кнопкой
  «Включить переключение».
- **«Нужно ваше действие»** — то, что без человека не решить: модему не хватает драйвера, интерфейс удалён вручную,
  веб модема просит пароль.
- **«Сбой самого роутера»** — умер USB-контроллер, паника ядра, перегрев, проседание питания, нехватка памяти, ошибки
  накопителя; после перезагрузки — с какими сбоями закончилась прошлая загрузка.
- **«Другие модемные помощники»** — если на роутере стоят сторонний менеджер модемов, sms-tool, 3ginfo и подобные, которые могут
  мешать.
- **Таблица каналов** («Подробный»): №, канал, устройство, статус, метрика (правится нажатием), трафик за сегодня,
  пик скорости, задержка проверки, почему так; стрелки меняют приоритет. Строкой ниже — когда проверяли связь.
- **Модемы** — карточками или таблицей (переключатель «Карточки / Таблица»). В карточке: модель или имя, оператор,
  технология и палочки сигнала, роль (основной, резерв, только вручную), трафик и скорость, итог проверки связи
  («Интернет · 57 мс», серое — устаревший результат), значки «🌐 Веб» (открыть веб модема) и «починено N раз за час».
  На «Подробном» ещё RSRP и SINR с единицами, агрегация, MIMO основной соты, температура и APN (с r168), значок «! N» — восстановления за час, сбрасывается нажатием (с r177), строка «SIM-карта» (с r175: вставлена и чья, не обнаружена,
  ждёт PIN/PUK, неизвестно — модем не в сети оператора).
  Кнопки: «Подключить / Отключить», «Проверить». Меню «⋯»: «Сделать основным», «Выключить подключение»,
  «Приостановить управление», «Замерить скорость» (с r168: ~20 с и 30–100 МБ трафика SIM, результат в строке
  карточки, разбор — на странице модема), «Убрать из списка» (для отключённого).
- **Модем без профиля** — плашка «знает не полностью» и кнопка отчёта.
- **«Порты и устройства»** — дерево USB: хабы, модемы, их интерфейсы и драйверы, журнал подключений.
- **«Все SMS»** (уровень «Подробный», свёрнута) — сообщения всех модемов одной лентой, новые сверху, с поиском по
  номеру, тексту и модему; сообщения самого оператора отмечены. Открытая лента берёт то, что служба уже прочитала, раз в
  30 секунд, модемы ради неё не опрашиваются и сообщения не помечаются прочитанными. «Открыть» ведёт во вкладку SMS модема.
  В «Подробном» у выбранного устройства — «Это модем?»: «Авто», «Модем» или «Это не модем», по VID:PID (с r179).
- **«Крайние меры: USB-контроллер и питание»** (страница модема, «Восстановление связи», с r180) — когда не помог ни один
  шаг: «Перезапустить USB-контроллер» (вместе с модемом отключится всё на этом контроллере, список показан заранее;
  недоступно, если там накопитель самого роутера) и «Выключить и включить …» для линий питания, которые показывает плата.
  Только вручную и после подтверждения.
- **«Похоже на модем»** — карточка устройства, которое MedveModem не признал модемом, хотя у него есть свои порты или
  его выпускает производитель модемов: «Считать модемом» или «Это не модем» (больше не спросит). Модем, которым
  управляет ModemManager, признаётся без вопроса (с r179).

## 5. Страница модема

Шапка: имя (✎ — переименовать), модель, оператор, сигнал, адрес, сессия, трафик, скорость; кнопки «Подключить»,
«Проверить соединение» и меню. Вкладки: «Обзор», «Сеть и сигнал», «SMS», «AT» (с «Подробного», если AT-порт у
движка), «Диагностика», «Настройки» (последней, выделена цветом темы). Карточки раскрываются и сворачиваются,
состояние запоминается.

### 5.1. «Обзор»

- **«Соединение»**: как подключён, адреса, интерфейс, сетевое устройство, шлюз, DNS оператора, MTU, метрика
  («Подробный»).
- **«Связь и трафик»**: проверка связи, текущая скорость, трафик за сессию, сегодня и месяц, «без интернета сегодня»,
  лимит трафика.
- **«Надёжность соединения»**: держится ли модем на USB, питание порта, наблюдение за состоянием, ограничения
  (например, пауза после частых сбоев); в «Подробном» — кто управляет, сессия, AT-порт.
- **«Журнал событий»**: лента за 24 часа и список событий — отключения, подключения, шаги восстановления, изменения
  настроек (⚠), вход в веб модема, перезапуски ModemManager и QModem; «Показать более ранние», «Скопировать журнал».
  Хранится 200 событий на модем.

### 5.2. «Сеть и сигнал»

- **Сеть**: технология, оператор, диапазоны, регистрация, код сети, сота (TAC / CID), базовая станция и она же на
  карте, расстояние до соты по TA, качество сигнала словами.
- **LTE** и **5G**: RSRP, RSRQ, SINR, RSSI со шкалой и словами («сигнал сильный, но помехи сильнее»).
- **«Агрегация частот»**: каждая несущая — диапазон, частоты канала ↓/↑, полоса, PCI, уровни.
- **«Соседние соты»** с кнопкой «Закрепить» (привязка к соте) там, где модем это умеет.
- **«Антенны · RSRP»** по цепочкам антенн; цепочка без измерения показана выключенной. **«Температура»** модема и
  усилителя (у Compal — уровень снижения мощности из-за нагрева).
- **«Режим сети и диапазоны»**: разрешённые технологии и приоритет, диапазоны, привязка к соте — «Изменить» с
  откатом, если интернет не вернулся. Защита привязки: если модем, привязанный к соте, долго без сети, привязка
  снимается сама (настраивается в «Настройки» → «Диагностика и компоненты»).
- **«История приёма»**: график RSRP/SINR за 5 минут, час, сутки, с подписями событий (привязка, переподключения).
- **«Трафик и скорость»**: график приёма и передачи за 5 минут, час и сутки — заливка средняя, пунктир — пик за 5 с.
  Считает роутер по счётчикам интерфейса, модем не опрашивается.

### 5.3. «SMS»

- **«Сообщения»**: переписки по номерам, новые сверху; непрочитанные залиты, у разговора в списке их число в скобках
  (пропадает, когда разговор открыт); отправка, удаление по одному и выбором, кнопка «Код» для цифр из SMS. Хранилище модема и «SMS в роутере» видны вместе.
- **«Контакты»**: записная книжка роутера (до 20 контактов, импорт `.vcf`); имена подставляются в SMS, в бот и в
  пересылку.
- **«USSD-запрос»**: код, кнопки кодов оператора, ответы в диалоге. Где USSD у модели не работает или рвёт LTE, карточка
  говорит заранее (FM350 — нет USSD, EP06 — «не подтверждён», LM960 — только в 3G, T99/T77 — уход в 3G на время
  запроса). У HiLink, ZTE и M150-4 USSD идёт через их веб.

### 5.3.1. «eSIM»

На всех уровнях, только у модема с eSIM: встроенный чип, о котором сообщает ModemManager, или чип, найденный кнопкой
«Проверить eSIM» в карточке «Проверка eSIM» на вкладке «Диагностика» (так находится и съёмная карта вроде 9eSIM; браузер запоминает это для модема).
«Прочитать eSIM» — EID (скрывается), свободная память, профили с оператором и состоянием; чтение занимает несколько
секунд и связь модема не трогает. «Включить» у выключенного профиля переключает на него после подтверждения: связь через
модем пропадает на 1–3 минуты, модем перечитывает SIM и подключается снова. Часть модемов (семья Foxconn SDX55: T99W175,
DW5930e) держит прежний профиль до перезапуска — страница советует «Перезагрузить модем». Под таблицей — те же шаги, что
на «Диагностике»: «Перезапустить соединение», «Перерегистрация в сети», «Перезагрузить модем» (каждый спрашивает). Загрузку и удаление профилей
пока рекомендуется делать на смартфоне приложением карты (9eSIM, eSIM.me) или EasyEUICC / OpenEUICC на Android.
У модема с двумя слотами читается слот, который сейчас используется; другой — после переключения слота в «SIM-карта».

### 5.4. «AT»

С уровня «Подробный» и только если AT-порт у движка. **«AT-консоль»**: команды с готовыми подсказками по модели,
история по дням (скрывается), копирование. **«AT-порт»** — в «Настройках».

### 5.5. «Диагностика»

- **«Модем и его состояние»**: «Устройство» (модель, прошивка, IMEI, USB-путь, VID:PID, драйверы интерфейсов, кто
  управляет и почему, последняя попытка подключения, порты), «Температура», «Драйверы и службы» — чего не хватает
  модему, с кнопкой «Установить …» и командой для SSH (`apk add …` / `opkg install …`).
- **«Сервисные действия с модемом»** — только у модемов, которых они касаются, каждое по кнопке с подтверждением:
  «Правило usb-modeswitch», «Режим флешки», «FCC-разблокировка» (Foxconn/Dell), «Режим USB» (выбор конфигурации
  USB, например у DW5821e).
- **«Восстановление связи»**: текущее состояние, последний запуск, ограничения; ступени по порядку с пометкой
  «Автоматически при сбое»; ход шага виден, остальные действия на это время недоступны.
- **«Проверки и данные для поддержки»**:
  - **«Проверка доступа к сайтам»** — тестовые сервисы (Google, YouTube, Telegram, сайты операторов и другие) прямо
    через этот модем: что открывается, что заблокировано, белые списки или нет интернета; проверка подмены DNS.
  - **«Скорость и раздача»** — спидтест через модем по кнопке (с предупреждением о трафике, 30–100 МБ): график по
    секундам и вывод по форме скорости — ровная полка на круглом числе (ограничение оператора), быстрый старт и
    обрезка после первых мегабайт (раздача или квота), скорость, гуляющая с сигналом (радио); советы: TTL, аппаратное
    ускорение, тариф, IMEI.
  - **«Проверка eSIM»** — есть ли в модеме чип eSIM, встроенный или карта вроде 9eSIM: результат остаётся в карточке,
    найденный чип открывает вкладку «eSIM» (и кнопка «Открыть вкладку eSIM»).
  - **«Сообщения ModemManager»** о портах модема и что они значат.
  - **«Отчёт о модеме»** для разработчика: профиль, насколько модем знаком, недостающие драйверы, ответы AT, как
    прочитан веб — без идентификаторов.
- **«Приостановка управления»** — заморозка модема (последней, как самое далеко идущее действие).

### 5.6. «Настройки» модема

- **«Подключение»**: «Кто управляет модемом» (первым пунктом, с подсказкой), APN (из базы по SIM или свой), тип IP,
  логин и пароль APN, DNS, фиксация TTL 64 (с предупреждением, если включено аппаратное ускорение NAT — тогда правило
  не действует на ускоренных соединениях), автоподключение. Изменения — транзакцией с откатом.
- **«SIM-карта»**: состояние, оператор SIM, номер; PIN; переключение слота у модулей с двумя слотами (обычный и eSIM).
- **«Веб-интерфейс модема»** (HiLink, ZTE, M150-4, UZ801): как читается веб, пароль («Забыть пароль»), ссылка
  открыть веб через роутер; «Данные модема» — адрес у оператора, трафик сессии, месяца и всего времени, прошивка,
  радиоканал; режим сети и диапазоны LTE; «Очистить счётчики» (HiLink).
- **«AT-порт»**: какой порт выбран и кем, «Найти AT-порт», выбор вручную.

## 6. «Настройки»

Общие для всех модемов роутера. Одна кнопка «Сохранить» под вкладками (кроме «Службы», где сохранять нечего) и
«Отменить изменения».

### 6.1. «Служба»

Таблица процессов: движок, Telegram-бот, ModemManager, QModem — PID, память, время работы, перезапуски за сутки,
падения движка с запуска роутера. «Перезапустить MedveModem» (интернет через модемы не пропадает), «Аварийный
перезапуск QModem» (с предупреждением; по умолчанию QModem только перечитывает настройки).

### 6.2. «Интернет и резерв»

- **«Приоритет каналов»**: порядок модемов и проводного WAN, «Применить порядок».
- **Автопереключение**: включено ли, что делать с каналом, который снова отвечает, каналы «только вручную».
- **Проверка связи**: «Основные адреса» и «Адреса белых списков», проверка TLS.
- **«Режим белых списков»**: менеджер (podkop 0.8 или forkop 2), секция, серверы туннеля — один или первый живой из
  отмеченных (галочками или по шаблону имени), «вся сеть через туннель» (с предупреждением: нужно не всегда),
  задержки включения и выключения; «Подсказать по спискам сообщества» отмечает серверы, чьи адреса открыты при белых
  списках; «Включить сейчас» / «Выключить сейчас», журнал. Классический podkop (до 0.8) и forkop 1.x переключать
  сервер на ходу не умеют — карточка так и говорит.
- **«Службы при появлении интернета»**: какие службы роутера перезапустить, когда канал поднялся.
  ZeroBlock, если он установлен, отмечен по умолчанию (с r167): он стартует раньше модема и иначе ждёт своей
  проверки до 10 минут. Для zapret и похожих обходов там же подсказка: на мобильном интернете и при белых
  списках они не помогают.

### 6.3. «Модемы»

С r174 всё, что относится к самим модемам, — на этой вкладке, а галочки внутри карточек разделены на группы.

- **«Обслуживание модемов»**: «Подключение и восстановление» (новый модем автоматически, восстановление связи,
  служебные порты), «Проверки» (межсетевой экран, перехват DNS оператором — выключена по умолчанию), «Веб-интерфейсы
  и обзор» (доступ к веб-странице модема через роутер, таблица на «Обзоре» OpenWrt).
- **«Подробные данные о сети»**: «Что читать с модемов» (уровни по антеннам; соседние соты и местоположение от
  ModemManager — выключены по умолчанию, на слабых платах вешали роутер) и «Привязка к соте и диапазонам» (через
  сколько без сети вернуть прежние настройки).
- **«Имена модемов»**: имена всех известных модемов в одном месте.

### 6.4. «Уведомления»

- **«SMS-оповещения»**: на номера из записной книжки — о пропаже интернета и других событиях; «Отправить тестовую
  SMS».
- **«Пересылка SMS»**: в ntfy/webhook; SMS-кой на номера (до 5) через выбранный модем или любой живой, кроме того, на
  который пришло; с каких модемов пересылать; ограничение в час.
- **«SMS в роутере»**: архив входящих, перенесённых из памяти модема. «Хранить все SMS в роутере» (с r169, по
  умолчанию выключено): каждое входящее сразу копируется во флеш роутера, из модема ничего не удаляется; если модем
  потерял сообщения (например, после перезагрузки), они остаются в списке из копии. Копии копятся в оперативной
  памяти и пишутся во флеш пачкой раз в 10 минут и при остановке службы (с r170).
- **«Telegram-бот»** — ссылка на его настройки.

### 6.5. «Диагностика и компоненты»

- **«Проверить сервисы»** по всем каналам.
- **«Обновление MedveModem»** (заготовка, r193): установленная версия, последняя в выпусках на GitHub (проверка при
  открытии, если прошлой больше часа), «Проверить обновления», «Обновить до …» с журналом. Архив под архитектуру и линию
  OpenWrt роутера сверяется с `SHA256SUMS` выпуска; ставятся движок и LuCI, бот — если он установлен; настройки остаются.
  Если прямой доступ к GitHub заблокирован — через локальные прокси. Источник — `medvemodem.core.update_repo` (по
  умолчанию `Medvedolog/medvemodem`), канал — `medvemodem.core.update_channel` (`bench` — стендовые сборки,
  `release` — только выпуски `v…`). Кнопки — у группы инженера, как у установки QModem.
- **База APN**: «Проверить и обновить».
- **QModem**: установка из архива сборки, журнал установки.
- **«Драйверы и ModemManager»**: что установлено, кнопки установки с журналом.
- **«Аварийно: ModemManager»** — перезапуск ModemManager (связь через его модемы пропадёт примерно на минуту).

## 7. Другие места в LuCI

- **«Состояние → Обзор»**: блок «Модемы» — есть ли интернет и через какой модем, по строке на модем.
- **«Сеть → Интерфейсы»**: интерфейсы модемов с протоколом `medvemodem` показываются как «MedveModem» (с r149), а не
  «Unsupported protocol type». Править их лучше на странице модема: там изменения идут с откатом.

## 7а. «Белые списки»

«Модем → MedveModem → Белые списки» (r185): всё про режим, когда оператор пропускает только свой список сайтов.

- **Сейчас** — каждый канал: открыт, только белый список, белый список с интернетом через туннель, нет ответа.
- **Проверка сервисов** — через выбранный канал или через «Все каналы» по очереди; для всех — таблица «сервис × канал».
  Тот же тест, что на странице модема; около 10 секунд и меньше 1 МБ на канал.
- **Локальные прокси** (r189) — прокси туннеля на роутере, через которые идут загрузки и установка пакетов, если
  GitHub или сервер пакетов OpenWrt напрямую заблокирован: смешанный прокси podkop, podkop-plus, forkop, netshift, порт
  SSClash, nikki или другого clash/mihomo. «Проверить» — запрос к GitHub и к downloads.openwrt.org через этот прокси.
  «Исправить» у найденного — своя запись с другим адресом, портом, логином или паролем: она встаёт на его место, а
  настройки самой программы не меняются (пустой пароль — остаётся прежний). «Добавить прокси» — свой, он пробуется
  первым. Свои записи — секции `proxy` в `/etc/config/medvemodem`.
- **Режим белых списков** (podkop 0.8, forkop 2) — перенесён сюда из «Настроек».
- **Как распознаются белые списки** — «Адреса белого списка» для проверки связи (перенесены из «Настроек»; основные
  адреса остались там).
- **Службы при появлении интернета** — та же карточка, что в «Настройках»: перезапуск туннелей, когда канал заработал.
- **Уведомления** — SMS-оповещение «работает только белый список» и его минуты (перенесены из «Настроек → Уведомления»,
  там же включаются сами SMS-оповещения и получатели); ссылки на уведомления бота в LuCI и в Telegram (`/settings`).
- **Советы** — DNS 77.88.8.8, обходы DPI, сервер туннеля на разрешённом адресе.

На старых местах в «Настройках» — строка «… — на странице «Белые списки»» со ссылкой.

## 8. Telegram-бот: страницы в LuCI

«Модем → MedveModem → Telegram-бот».

- **«Обзор»**: что бот делает сейчас — запущен ли, токен, администратор, получение команд и отправка уведомлений,
  сертификаты и часы, очередь. **«Пути к Telegram»** — все пути, которыми ходит бот (напрямую, через туннель роутера,
  через прокси, через модемы, аварийные IP): по строке на путь, состояние для команд и для отправки, «Проверить» (в
  очередь, ход проверки виден). Если на роутере есть SSClash или nikki без mixed-порта, над путями — совет его
  включить. Кнопки «Обновить», «Перезапустить бота», «Отправить тестовое сообщение»; предупреждение о конфликте 409,
  если бот с этим токеном запущен где-то ещё.
- **«Мастер настройки»**: токен от @BotFather → администратор по Telegram ID (бот ловит первое сообщение) → проверочное
  сообщение. «Проверить без прокси» идёт действительно без прокси. Если Telegram напрямую недоступен — сначала прокси.
- **«Настройки»**: включение бота, язык, что разрешено (показывать текст SMS, пересылать SMS, управлять модемами,
  менять настройки из Telegram), режим получения команд и отправки (авто, только прокси, только напрямую), запасной
  путь через другие модемы, интерфейс для прямого пути; «Прокси до Telegram» — свои прокси (SOCKS5 как `socks5h://`
  или HTTP(S) CONNECT), их порядок относительно найденных на роутере, «Логин и пароль прокси» (один на все,
  заданные здесь); аварийные IP Telegram (с проверкой сертификата).

## 9. Telegram-бот: в Telegram

### 9.1. Как пользоваться

Бот отвечает только администратору. Внизу — кнопка «☰ Меню» со списком команд и подсказками; постоянной клавиатуры под
полем ввода нет (с r149). Экран бота — одно сообщение, которое обновляется кнопками под ним («🔄 Обновить», «◀️
Назад»), а не стопка новых.

| Команда | Что |
|---|---|
| `/menu` | сводка и кнопки разделов |
| `/status` | роутер и модемы: интернет, через что, за сутки (сколько раз и сколько всего пропадал), нагрузка и память служб, перезапуски ModemManager и QModem |
| `/modems` | список модемов (первым — тот, через который интернет) и карточка модема |
| `/channels` (`/uplinks`) | интернет-каналы по порядку, их состояние, «БС» |
| `/sms` | входящие SMS (если показ разрешён) |
| `/send` | отправить SMS: модем, номер или контакт, текст, проверка, «Отправить» (если разрешено «Разрешить отправку SMS и USSD из Telegram») |
| `/ussd` | USSD-запрос: код оператора кнопкой или свой, ответ сети, ответ на меню сообщением (то же разрешение) |
| `/network` | «🌍 Сеть»: адреса основного маршрута и модемов, внешние IP, podkop/forkop и туннель, проверка сервисов; режим белых списков и тест блокировок — кнопкой «🚧 Белые списки» в меню |
| `/quota` | лимиты трафика |
| `/events` | последние события с подробностями |
| `/log` | журнал модемов файлом |
| `/logall` | весь журнал роутера файлом (номера, идентификаторы, ссылки прокси, токены скрыты) |
| `/settings` | «⚙️ Настройки»: оповещения и прокси |
| `/help` | справка |

### 9.2. Карточка модема

Оператор, сигнал словами и цифрами, роль, сколько сегодня не было интернета и сколько раз пропадал, трафик. Кнопки
(если в LuCI разрешено управление; действия, которые рвут связь, спрашивают «✅ Да / ✖️ Отмена»): «🔁 Переподключить»,
«⏹ Отключить» / «▶️ Подключить», «➡️ Первым среди модемов» (проводной WAN остаётся первым, если он выше), «🧊
Приостановить управление» / «☀️ Возобновить управление». На странице каналов — «🚫 Исключения автопереключения».
Результат действия — одним из четырёх: выполнено, выполняется, выполнено с предупреждением, не выполнено.

### 9.3. «🌍 Сеть»

Адреса основного маршрута и каждого модема; по кнопке — внешние IP через каждый канал. Установлен ли podkop/forkop,
версия, работает ли sing-box, идёт ли DNS роутера через него, выход через туннель. «🧪 Проверка сервисов» через
выбранный канал.

### 9.3а. «🚧 Белые списки»

Отдельная кнопка меню (r185): каждый канал — открыт, только белый список, через туннель, нет ответа; режим белых списков —
состояние и, при разрешённом управлении, «Включить / Выключить»; «🚦 Тест блокировок»: после предупреждения бот проверяет
сервисы через каждый модем — 🟢 без блокировок, 🟡 частичные, ⚪ белые списки, 🔴 интернета нет.

### 9.4. Уведомления

Одна ситуация — одно сообщение, которое обновляется, а не поток. О чём: пропал и вернулся интернет, канал ушёл в белые
списки, резервные модемы, перезапуски и остановка ModemManager и QModem, лимиты трафика, сбои самого роутера, новые
SMS (если разрешено), режим белых списков включён/выключен/сменил сервер. После перезапуска MedveModem бот 2 минуты
молчит и присылает одну тихую сводку.

«⚙️ Настройки» → режим: умные, только важные, все сразу, выключены; виды уведомлений; **тихие часы** — в эти часы без
звука, ничего не теряется; «нет интернета» и исчерпанный лимит — со звуком, если не выключено.

### 9.5. Прокси до Telegram

Бот перебирает пути по порядку: свои прокси «перед найденными», найденные на роутере, свои «после», затем напрямую,
через другие модемы, через аварийные IP. Найденные на роутере — mixed/SOCKS-входы, которые уже работают:

- podkop (0.7 и 0.8), podkop-plus, forkop (1.x — в секциях, 2.0 — «сервер» протокола mixed), NetShift — с логином
  входа, если он задан;
- **SSClash** (`/opt/clash/config.yaml`) и **nikki** (`/etc/nikki/run/config.yaml` или его UCI): их `mixed-port`
  с логином из `authentication`. Если mixed-порта нет, бот в «Настройках» и «Прокси» первым делом советует его
  включить: у SSClash — строкой `mixed-port: 7890` в конфиге и перезапуском Clash, у nikki — «Mixin → Mixed Port».
  Сам бот их конфиги только читает.

В «🌐 Прокси» видно, какой путь сейчас, причина отказа каждого («никто не принимает соединения», «нет ответа за 8 с»,
«прокси отказал», «Telegram не принял токен»); прокси можно добавить сообщением (`socks5h://…`, ссылка
`t.me/socks?…`) — бот сразу удаляет это сообщение и проверяет прокси.

### 9.6. Что бот не делает

Не помечает SMS прочитанными и не удаляет их; не пишет в журнал тексты SMS, ответы USSD, PIN и ссылки прокси (в
syslog — только название действия: `admin_cmd_status` и подобные); не управляет модемами, если управление не
разрешено в LuCI.

## 10. Файлы, журнал, безопасность

| Где | Что |
|---|---|
| `/etc/config/medvemodem`, `/etc/config/medvemodem-bot` | настройки (меняются из LuCI; правка руками — `uci commit medvemodem`) |
| `/etc/medvemodem/` | состояние на флеше: архив SMS, контакты, журнал режима белых списков |
| `/etc/medvemodem-bot/` | токен и пароли бота (0600), его состояние |
| `/var/run/medvemodem/` | оперативное состояние |
| `logread -e medvemodem`, `logread -e medvemodem-bot` | журнал |

- **Сеть.** MedveModem никогда не перезапускает сеть или Wi-Fi целиком: только свои интерфейсы (`ifup` / `ifdown`).
  Интерфейс модема, оставшийся без зоны фаервола, возвращается в `wan`; перенесённый в другую зону не трогается.
- **Права.** Службы работают от root, как службы самого OpenWrt; ubusd не трогается.
- **Приватность.** IMSI, ICCID и тексты SMS не пишутся в журнал и не хранятся сверх архива SMS, который включает
  владелец. Отчёт о модеме — без идентификаторов.
- **Чужие менеджеры.** podkop, forkop, SSClash, nikki, QModem MedveModem не ставит и не перенастраивает сам; исключение —
  режим белых списков, который включает владелец: он меняет сервер и `fully_routed_ips` секции podkop/forkop, записав
  прежнее в журнал, и возвращает всё обратно.

## 11. Конфигурация и профили изнутри

Для тех, кто правит руками, пишет профиль или разбирает отчёт. Всё, что здесь, LuCI и бот меняют сами; руками —
только `uci set …` и `uci commit medvemodem` (никогда `uci commit` без имени пакета).

### 11.1. `/etc/config/medvemodem`

Один файл, секции по типам. Модем указывается своим идентификатором: в секциях `modem` и `esim` — опция `device_id`,
в секции `device` — опция `id` (значение то же):

| `device_id` | Когда |
|---|---|
| `usb-serial:<серийник>` | у модема свой серийный номер USB, не общий с клонами |
| `usb-port:<путь>@<порт>` | серийника нет, он общий или это телефон; привязка к USB-порту |

| Секция | Что хранит |
|---|---|
| `core 'core'` | служба целиком: `enabled`, автоподключение, автовосстановление, починка интерфейсов, адреса проверки связи (`reach_target`, `reach_restricted`), опрос SMS и архив, клеточная информация, автосуспенд USB |
| `modem` | имя модема (`device_id`, `name`) |
| `device` | настройки модема: кто управляет, композиция USB (`usb_config`), лимиты трафика (`quota_*`), пароль веба (`web_password`), радио, восстановление |
| `sim` | подпись SIM-карты, которую вписал владелец: номер, описание, SMS-центр |
| `contact` | адресная книга SMS |
| `sms_forward 'sms_forward'` | пересылка SMS: ntfy или вебхук (`web`, `kind`, `url`), по SMS (`sms`, `sms_number`, `sms_contact`, `sms_parts` — по умолчанию 3 склеиваемые части, `sms_max_per_hour`), с каких модемов (`modems_all`, `modem`) |
| `alerts` | SMS-уведомления о связи и их пороги |
| `ussd` | сохранённые USSD-коды модема |
| `usb_port` | пометки USB-портов |
| `esim` | профили eSIM модема |
| `wlmode` | режим белых списков: менеджер, секция, серверы, LAN и роутер |

Токен ntfy/вебхука в этом файле не лежит: он в отдельном файле `/etc/config/medvemodem-secret` с ограниченными
правами, который форма настроек обратно не показывает.

**Как настройки находят модем в другом порту.** Секции `modem`, `device`, `esim` модема с `usb-port:`-идентификатором
переезжают за ним по соли и хэшам, сами идентификаторы не пишутся:
- `imei_key` — солёный хэш IMEI;
- `sim_key` — солёный хэш «IMEI | IMSI» (или «USB-опознание | IMSI»): различает два модема с одним IMEI.

Соль — `/etc/medvemodem/id-salt`. Если одинаковый IMEI виден у двух модемов сразу, слежение по IMEI для него выключается
(`imei-shared.json`), остаётся SIM-ключ.

### 11.2. `/etc/config/medvemodem-bot`

| Секция | Что хранит |
|---|---|
| `bot 'main'` | включён ли бот, язык, режим сводок, что разрешено (управление и прочее) |
| `administrator 'primary'` | кому бот отвечает (chat id) |
| `transport 'poll'`, `transport 'send'` | как бот получает и отправляет: напрямую или через прокси |
| `notifications 'events'` | какие события присылать |
| `proxy 'backup1'` … | резервные пути до Telegram |

Токен бота и пароли прокси — в отдельном UCI-файле `/etc/config/medvemodem-bot-secret` (секция `secret 'main'`,
опция `token`; root, права 0600, их ставит и проверяет `init-secrets`), обычная форма его не показывает. В
`/etc/medvemodem-bot/` — соль бота и его постоянный снимок состояния.

### 11.3. Состояние: что где лежит

На флеше — `/etc/medvemodem/` (пишется редко, переживает перезагрузку):

| Файл | Что |
|---|---|
| `id-salt`, `diag-salt` | соли для ключей модемов и для отчёта |
| `identity.json` | последняя модель каждого модема (профиль применяется до того, как ModemManager его увидит) |
| `imei-shared.json` | IMEI, замеченные на двух модемах сразу (в виде хэшей) |
| `web-models.json` | модели модемов-роутеров по их вебу |
| `frozen.json`, `deactivated.json` | приостановленные и отключённые модемы |
| `radio-txn.json`, `radio-guard.json` | изменение радио в процессе и сторож привязки к соте/диапазонам |
| `traffic.json`, `traffic-peaks.json`, `sim-usage.json` | счётчики трафика и лимиты |
| `downtime.json` | простои каналов |
| `sms-seen.json`, `sms-archive.json`, `sms-alert.json` | какие SMS уже видели (без текста), архив SMS в роутере (включает владелец), очередь уведомлений |
| `dns-check.json` | последняя проверка DNS |
| `wlmode.json` | журнал отката режима белых списков: что добавлено в настройки podkop/forkop и что вернуть при выключении; удаляется, только когда всё возвращено |
| `managed.json`, `journal.json` | какие поля сетевой конфигурации (`network`, `firewall`) записал MedveModem и незавершённая транзакция её изменения: по ним он не трогает правки владельца и доводит или откатывает прерванную запись |
| `neighbours.json`, `tunnel.json` | соседние соты, туннель |
| `usbmode-huawei.json` | переключения композиции Huawei |

В памяти (пропадает при перезагрузке): `/var/run/medvemodem/` — оперативное состояние движка и задания помощников;
`/tmp/medvemodem/history.json` — журнал событий модемов текущей загрузки; `/tmp/medvemodem-bot/` — бот.

### 11.4. Профили модемов

Профиль — JSON в `/usr/share/medvemodem/profiles/generic/`, схема — `profiles/schema.json` в исходниках, проверка —
`tools/validate_profiles.py`. Пакет перезаписывает этот каталог при обновлении, поэтому свой профиль держите в
исходниках и присылайте в проект: отдельного каталога для своих профилей пока нет.
Изменения подхватываются без перезапуска службы, в течение минуты.

**Выбор профиля.** Каждый профиль из `match` получает очки, побеждает наибольшее:

| Условие `match` | Очки |
|---|---|
| `pid` | 100 |
| `vid` | 80 |
| `mm_model_contains` (модель от ModemManager) | 80 |
| `mm_manufacturer_contains` | 60 |
| `drivers_any` (драйвер интерфейса) | 50 |
| `manufacturer_contains`, `product_contains` (строки USB) | по 30 |
| `bus` | 20 (`usb`) / 1 (`any`) |

Если хоть одно условие не совпало, профиль выбывает. Поэтому у одного VID:PID может быть несколько профилей:
например, по драйверу или по модели из ModemManager.

**Поля профиля:**
- `id`, `description`;
- `extends` — наследование от профиля семейства; `abstract` — база, которая сама не выбирается;
- `fit` — `family` или `generic`: модем узнан не полностью, LuCI предложит отчёт;
- `policy` — кто управляет (`owner_priority`: ModemManager, QModem, сам движок, веб), можно ли AT при
  ModemManager, порты для ModemManager (`mm_ports`), FCC-разблокировка (`fcc_unlock`);
- `hints` — протоколы, номера AT-интерфейсов, композиции USB (`usb_configurations`), режим роутера, USSD,
  заголовок плашки (`title`, до 60 знаков);
- `dial` — дозвон движком по AT (`{cid}`, `{pdp}`, `{apn}`);
- `bind` — привязка драйвера к AT-порту на стороне роутера;
- `radio` — AT-диалект настроек радио;
- `recovery` — ступени восстановления (сессия, радио, мягкий сброс, перепривязка драйвера, USB, питание),
  `settle_ms`, источник сведений.

**Статус ступеней восстановления.** Сам движок запускает только проверенное:
- `bench-validated` — проверено на нашем стенде, ступени идут автоматически;
- `field-reported` — сообщено с реальных роутеров или из документации: автоматически только мягкие ступени,
  разрешённые правилом, остальные — по кнопке.

**Остальное в `profiles/`:**
- `presets/` — готовые AT-команды и USSD-коды;
- `apn/` — база APN по операторам (по коду из IMSI);
- `catalog/` — каталог железа и известных композиций USB, по нему модем без профиля получает профиль семейства.
